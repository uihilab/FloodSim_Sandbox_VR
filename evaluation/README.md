# Evaluation

Scripts, inputs and outputs for three supporting analyses of FloodSim Sandbox:

| Folder | Analysis |
|---|---|
| `c1_grid/` | Sensitivity of inundation extent, depth, velocity and building-scale exposure to hydrodynamic grid resolution (0.5, 1, 2, 4 m), with stage calibration and validation at USGS gage 05454500 |
| `c2_hazus/` | Validation of Hazus depth-damage functions against 2008 NFIP claims (Johnson and Linn Counties, Iowa) and Monte Carlo uncertainty of the loss estimates |
| `c3_ai/` | Technical evaluation of the GPT-4o-mini analysis module against simulation-derived ground truth, an image-only / data-only / combined input ablation, and an image-data conflict test (also run with gpt-5.6-terra and gpt-6.1-sol) |
| `data/` | Public inputs and their provenance (`provenance.json` in each subfolder) |

## Setup

Python 3.12 or later. The hydrodynamic solver runs on an NVIDIA GPU through CuPy.

```
pip install -r requirements.txt
```

## Reproducing

**Grid sensitivity** (`c1_grid/`)

```
python fetch_inputs.py        # USGS 3DEP 1 m DEM + OpenStreetMap buildings
python calibrate_channel.py   # channel depth calibrated to the USGS rating at 05454500
python run_experiment.py      # 3 discharges x 4 cell sizes, to steady state
python run_record2008.py      # June 2008 peak (validation and AI-evaluation scenes)
python metrics.py             # tables and figures in results/
```

`INENGINE_PROTOCOL.md` describes the equivalent comparison inside Unreal Engine with Fluid Flux.

**Damage validation** (`c2_hazus/`)

```
python fetch_data.py          # OpenFEMA NFIP claims, Hazus FAST depth-damage tables
python analysis.py            # outputs in out/
```

**AI evaluation** (`c3_ai/`). This needs the 0.5 m runs from `c1_grid/` and an OpenAI API key in
`OPENAI_API_KEY`. The key is read from the environment and is never written to the logs.

```
python fetch_scene_inputs.py  # NAIP orthoimagery + named OpenStreetMap features
python render_scenes.py       # scenes/images/ and scenes/manifest*.csv
python run_eval.py --k 10 --workers 8                               # deployed model, all conditions
python run_eval.py --model gpt-6.1-sol --conditions A,C0,J,K,PJ,PK  # other models
python run_eval.py --conditions K,PK --manifest scenes/manifest_mismatch.csv
python score.py --embeddings                                        # per model: --log/--out
python headline_metrics.py
python ablation.py --models gpt-4o-mini gpt-5.6-terra gpt-6.1-sol
python conflict_judge.py
python tests/test_metrics.py
```

The scene images, raw model responses (`results/**/responses.jsonl`, 6,780 calls made on 2026-10-23)
and the coder caches are included. Re-running `score.py` therefore reproduces the scored results
without new API calls; the per-response scored tables are regenerated by `score.py` and are not
stored.

## Not included

The following are regenerated by the scripts above:
- the 3DEP DEM and NAIP imagery
- the solver output fields (`*.npz`)

## Data sources

- **USGS 3DEP** 1 m DEM: The National Map.
- **USDA NAIP** orthoimagery: USGS The National Map ImageServer.
- **OpenStreetMap** contributors (ODbL), via the Overpass API.
- **USGS NWIS** ratings and peaks for gages 05453520 and 05454500 (in `data/c2/usgs/`).
- **OpenFEMA** FimaNfipClaims v3.
- **FEMA Hazus FAST repository** (https://github.com/nhrap-hazus/FAST): depth-damage tables.
